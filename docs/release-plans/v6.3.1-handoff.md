## Decisions made

### 1. ORM models stayed in `app/models/auth.py`, not moved into `tenant.py` / `user.py`
**Why:** The v6.3.1 prompt referenced files at `backend/app/models/tenant.py` and `backend/app/models/user.py` that don't exist (the empty `user.py` placeholder is 0 bytes; `tenant.py` is absent). The actual `Tenant` and `User` classes live in `auth.py` and have since v1.0; ten+ files import them from there. Splitting them out would either create back-compat shims (dead code) or require an import sweep, both out of scope for "schema and lookup helpers only." User confirmed Option A (edit in-place in `auth.py`).
**Impact for v6.3.2:** Continue editing `auth.py`. Don't be misled by the prompt's path references.

### 2. `proprietor` is a synonym for `owner` everywhere top-tier is checked
**Why:** User feedback during v6.3.1: "for me owner proprieter both are same and would use interchangeably." The legacy register flow (`auth_service.register_tenant_and_user`) writes `role="proprietor"`; the v6.4 spec uses `role="owner"`. Until v6.3.2 runs the role-rename migration, both spellings live in the database and both must grant top-tier access.
**Impact for v6.3.2:** Either run a one-shot UPDATE that rewrites `'proprietor'` → `'owner'`, *or* keep `proprietor` in `TOP_TIER_ROLES` and `VALID_USER_ROLES` indefinitely. If the rewrite happens, drop `proprietor` from both sets in the same commit.
**Memory entry:** `memory/feedback_role_synonyms.md`.

### 3. Service-layer role validation, not DB-level
Per existing convention in migrations 017, 018, 023: the migration uses plain `String(20)` columns; allowed-value validation lives in `app/services/role_helpers.py`. No SQLAlchemy `Enum` types added.

### 4. The migration's `downgrade()` does not "restore the v6.3.0 role validator"
The v6.3.1 prompt instructed `downgrade()` to "restore the role validator to the v6.3.0 set," but no role validator existed at v6.3.0 — there was nothing to restore. Service-layer Python helpers are reverted via `git`, not via `alembic downgrade`. The migration's `downgrade()` therefore handles only DB schema (drops every added column + the `idx_users_phone_e164` index). The `role_helpers.py` file would simply be removed by checking out the v6.3.0 commit. This interpretation is documented in the migration file's docstring.

### 5. Backfill behavior on a freshly-migrated DB
The backfill reports `fixed=0` on a normal v6.3.1 deploy because every existing row already received its `server_default` at migration time. The script earns its keep on partially-applied schemas, on rows imported via raw SQL that bypassed defaults, and on test fixtures — covered by `test_seeded_db_3_rows_updated` which writes empty-string values directly to simulate that case.

### 6. Migration tests are file-integrity, not live-DDL
Following the existing `test_alembic_migrations.py` convention. Live PG upgrade/downgrade is a manual verification gate (run by hand before tagging), not an automated test, because the conftest uses SQLite which doesn't support every PG-only DDL pattern used elsewhere. The 50 new tests cover the migration's source structure, the ORM's column visibility, and the round-trippable `_TENANT_COLUMNS` / `_USER_COLUMNS` symmetry.

## Gotchas encountered

1. **Existing roles in DB are `proprietor` and `scheduler`**, not `owner / manager / viewer` as the v6.3.1 prompt's "context" section claimed. The prompt was forward-looking; the codebase reality is two roles, both still in use. `is_top_tier` on existing `proprietor` accounts returns True (per decision 2); `scheduler` returns False.

2. **`backend/app/models/user.py` is an empty 0-byte file** dating from project init (2025-03-23). Left alone — deleting it is out of scope for v6.3.1.

3. **`server_default` for `Time` columns** — passed as ISO string `"07:30:00"`, not as `sa.text(...)` or `time(7,30,0)`. Works on both SQLite (test) and PostgreSQL (prod). Verified by `test_tenant_briefing_morning_time_default`.

4. **PhoneTenantMap import cycle** — `app/models/whatsapp.py` now imports `TOP_TIER_ROLES` from `app/models/auth.py`. This is a downward dependency (whatsapp → auth, never the reverse), so no cycle risk.

5. **The conftest `_patch_pg_types_to_json` helper** runs at import time; new columns of type `Time` and `Boolean` use cross-dialect types and don't need patching.

6. **Migration head tracking** — `test_head_is_023` was renamed to `test_head_is_027`. Future iterations need to bump this assertion in lockstep with each migration.
