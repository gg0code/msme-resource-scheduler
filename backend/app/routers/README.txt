ARCHITECTURE NOTES:
All routers are registered in main.py and serve as the HTTP interface layer between the React frontend and backend services. Each router handles a specific domain (jobs, employees, machines, etc.) and delegates business logic to services layer while using crud layer for database operations. The auth.py router provides JWT tokens that other routers consume via dependencies.py middleware for authentication and tenant scoping. The scheduler_router.py orchestrates the core scheduling engine while other routers provide supporting CRUD operations and data for the scheduling system.

Principle 2 applies critically - every endpoint must enforce tenant scoping through get_current_user dependency to prevent cross-tenant data leakage. GOTCHAS:
Never create endpoints without tenant_id filtering as this creates security vulnerabilities across the entire multi-tenant system. Always use the get_current_user dependency from core/dependencies.py rather than implementing custom authentication logic in individual routers. Feature-gated endpoints must use the require_feature decorator and handle FeatureNotEnabledError exceptions properly to avoid breaking API contracts when features are disabled.
